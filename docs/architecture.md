# Архитектура Warhammer Archive

## Разделение кода и пользовательских данных

Репозиторий содержит только приложение, документацию и синтетические тесты.
Пользователь выбирает отдельные каталоги для исходной библиотеки и генерируемых
данных.

```text
Warhammer Library/       исходные PDF и сканы, только чтение
Warhammer Archive Data/  каталог, OCR, индексы, кеш и настройки
AI Models/               локальные OCR-, embedding- и LLM-модели
Warhammer Archive/       установленное приложение
```

Пути не должны быть зашиты в код. Исходный файл идентифицируется относительным
путём внутри выбранной библиотеки и контрольной суммой SHA-256.

## Конвейер

```text
Аудит -> Извлечение/OCR -> Нормализация -> Индексы -> Поиск -> RAG -> Проверка цитат
```

LLM является последним этапом. Она не заменяет поиск и не считается источником
фактов.

## Основные правила данных

- оригинальные PDF никогда не изменяются;
- исходный и очищенный текст в будущих версиях хранятся раздельно;
- каждый фрагмент сохраняет связь с документом, PDF-страницей, печатным номером
  страницы и координатами исходного блока;
- разные редакции и типы источников не объединяются автоматически;
- английский оригинал остаётся каноническим слоем для цитирования;
- русский словарь и перевод используются для поиска и формирования ответа;
- полнотекстовый и векторный индексы строятся локально каждым пользователем.

## Формат аудита v0.1

`summary.json` содержит агрегированную статистику. `documents.jsonl` хранит одну
JSON-запись на документ, благодаря чему отчёт можно обрабатывать потоково даже
для большой библиотеки.

Аудитор не сохраняет извлечённый текст. Он фиксирует только количество символов,
слов, изображений, примерное покрытие страницы изображениями и классификацию.

Классы страниц:

- `text` — достаточно извлекаемого текста;
- `sparse_text` — текстовый слой есть, но текста мало;
- `scan_candidate` — большая часть страницы занята изображением, текста мало;
- `image_only` — присутствуют изображения без извлекаемого текста;
- `empty` — текст и изображения не обнаружены;
- `page_error` — страницу не удалось проанализировать.

Классификация служит для планирования следующего этапа и не заменяет полноценный
layout-анализ.
